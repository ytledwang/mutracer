一、引擎源码核证（Epic GitHub 5.5.4-release，用户已挂 Epic-GitHub 授权）
源码存 ~/mutracer-scratch/ue55-src/（PathTracing 38 文件 + RectLightComponent/LightComponent/PostProcessEyeAdaptation/PostProcessTonemap/RectLightSceneProxy 等）。关键链路（file:line 实证）：
- 面光 radiance：ComputeLightBrightness = I*100^2 [RectLightComponent.cpp:174]；proxy Color=LightColor*I*1e4 [LightComponent.cpp:1467]；GetLightShaderParameters 除以 0.5*W*H [RectLightComponent.cpp:313] => nits = 2*I_cd/A_m2（UE 约定含 x2）。
- PathTracer 直接以该值为 radiance 采样（PathTracingRectLight.ush "stored color is radiance"），曝光不烘进灯色（InverseExposureBlend 默认 0 [LocalLightComponent.cpp:21]，PathTracing.cpp:2746 的乘法为无效操作）。
- 显示层：tonemap 前 display_linear = nits * 2^AutoExposureBias * 0.18（AEM_Manual + ApplyPhysicalCameraExposure=false => WhitePoint=1 [PostProcessEyeAdaptation.cpp:436]；TargetExposure=L/0.18 [usf:162]；GlobalExposure=Comp*0.18 [usf:183]；tonemap 乘 GlobalExposure [PostProcessTonemap.usf:529]）。灶机相机 exposure=1 => 因子 0.36。
- 点光：Color=LightColor*I_cd 无面积除法，与 mutracer 4*pi*I/683 等价，无误差。

新发现：8 盏面光能量翻倍，前视亮度几乎不动（+0.10/255）。灯光对当前成片的直接贡献极小，fg_lum 19.45 的主力是背景/环境反射。因此：
- 单位换算 2 倍差是真 bug 且已修，但不是黑灶面主因；
- 灶面黑的剩余缺口在灯光路径的显示缩放，已定位到代码级：ue_filmic.py:78 ue55_exposure_scale = 2^bias/1.2，且直接作用于 Cycles 辐射度 radiance（W）。UE 引擎（已核源码）对光度 nits 用 2^bias*0.18。折算到同一输入，mutracer 灯光路径相对 UE 差 683*0.18/1.2 = 147.5x —— 这就是 0.532W"照不亮灶面"的定量解释（env/skylight 路径当年用 k=3.1 拟合金样，吸收了这个因子，所以 329c 无灯对照是好的；灯光路径没有对应补偿）。
- 另注：mutracer 的 1.2 来自 UE 旧版 lens attenuation 0.65 约定（"1.0cd/m2->1.2"）；UE 5.5 默认 q=0.78（"1.0->1.0"），且 tonemap GlobalExposure 含 0.18 灰基准——1.2 和 0.18 两个因子在灯光路径上都没有。
- 注意：相机 post 还有 contrast=1.1/saturation=1.2/temperature=6500 待对齐核证（ue_filmic 已实现后三者，曝光尺度如上）。
